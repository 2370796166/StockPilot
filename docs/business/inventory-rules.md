# 库存业务规则

MySQL 是库存唯一权威来源。Redis 缓存、锁或 RabbitMQ 消费成功不能决定库存最终正确性。

## 维度与数量

库存唯一维度为 `warehouse_id + location_id + sku_id`，库位必须属于对应仓库。数量为 `DECIMAL(19,4)`，Java 使用 `BigDecimal`。

```text
actual = available + frozen
actual >= 0
available >= 0
frozen >= 0
```

actual 为仍在实体仓库内的实际量，frozen 为已占用但未离仓的量，available 为可继续分配的量。当前三个字段均持久化，通过 Java 不变量、数据库 CHECK 和条件更新保证关系。

| 操作（Q > 0） | actual | available | frozen |
|---|---|---|---|
| 采购完成 | +Q | +Q | 0 |
| 销售/调拨冻结 | 0 | -Q | +Q |
| 销售出库/源仓调出 | -Q | 0 | -Q |
| 取消释放 | 0 | +Q | -Q |
| 目标仓收货 | +Q | +Q | 0 |
| 盘盈/盘亏调整 | 差异 | 差异 | 0 |

## 事务、并发与幂等

- 库存统一通过库存 Service 写入，采购、销售、调拨、盘点不得直接更新库存表。
- 单个业务动作的单据状态、余额、流水和相关在途/锁记录必须在同一 MySQL 本地事务中变化；多明细任一失败整单回滚。
- 禁止“先查可用量再无条件更新”。冻结检查可用量下限，出库/释放检查冻结量下限，并检查条件更新影响行数。
- 预期版本条件、单据行锁、稳定的多明细处理顺序和数据库唯一约束共同处理并发。
- 同一业务动作不得重复生效。业务单号、明细维度和流水业务动作唯一键是最终幂等防线。
- 流水记录三数量前值、差量、后值、业务来源、操作人和版本链，只新增或查询，普通接口不能修改/删除库存核心数据。
- 入出库完成事务只写 Outbox；RabbitMQ 在提交后处理允许延迟的预警，不承担库存冻结或扣减。

## 单据状态与限制

| 单据 | 主流程 | 取消/锁规则 |
|---|---|---|
| 采购 | DRAFT → SUBMITTED → APPROVED → COMPLETED | 仅草稿可编辑；没有取消或拒绝 |
| 销售 | DRAFT → RESERVED → APPROVED → COMPLETED | RESERVED / APPROVED 可取消为 CANCELLED 并释放 |
| 调拨 | DRAFT → SUBMITTED → APPROVED → OUTBOUND_COMPLETED → IN_TRANSIT → COMPLETED | SUBMITTED / APPROVED 可取消；调出后禁止普通取消 |
| 盘点 | DRAFT → COUNTING → SUBMITTED → APPROVED → ADJUSTED | 创建即锁定选定维度；调整完成释放，没有取消/退回 |

调拨在途事实独立建模，不同时计入源仓或目标仓余额。盘点保存实际/可用/冻结/版本快照；差异为实盘减账面实际量，实盘不得小于冻结量。无差异调整也保留流水事实。盘点维度锁不等于冻结数量。

## 查询与 AI 解释边界

- 一页流水不等于完整历史，冻结/释放不等于实际出库，调拨/盘亏不等于销售消耗。
- 时间段汇总限定一个商品、一个仓库、可选库位和最多 92 个自然日；Asia/Shanghai 下起止日均包含，SQL 为开始日零时至结束日次日零时的半开区间。
- 各动作汇总覆盖全部匹配流水，只代表该范围差量，不重建期初/期末余额或证明版本链完整。
- 当前有效冻结来源只包括销售 RESERVED/APPROVED 和源端调拨 SUBMITTED/APPROVED；取消、完成、调出、在途和盘点锁均不计入当前冻结。
- 余额、有效来源总量和分页明细共享短期只读快照；总量一致不能证明逐库位/逐单据一致，不一致保留差异，不自动修正数据。
- 每个工具独立校验业务读取权限；数量由后端计算，同名候选需选择，缺参需澄清，查询失败不能展示为零库存。
- 安全库存按仓库/库位/SKU阈值判断，最新可用量严格低于阈值时打开预警，恢复到阈值及以上时解除。
