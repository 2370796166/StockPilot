## 优先处理的正确性问题

### P1：盘点异常没有正常恢复路径

证据：`InventoryCountApplicationService.create` 创建单据即写入维度锁；`recordResults` 只允许 COUNTING；`adjust` 要求 APPROVED，只有全部调整成功才删除锁。`InventoryMutationApplicationService.adjustInventoryCount` 拒绝实盘小于冻结量，而库存冻结、释放和出库 SQL 都拒绝存在盘点锁的维度。

例如冻结为 60、实盘为 50：可以录入、提交和审核，但调整失败。错误提示要求先处理占用业务，可是销售取消释放、销售出库和调拨取消也受同一个盘点锁阻止。没有退回或取消路径，业务人员无法通过正常接口恢复。这是业务闭环缺口，不能通过伪造实盘或直接删除锁解决。

建议另行明确取消/退回的状态、权限、操作原因和审计，使用本地事务同步处理单据与维度锁；录入/提交时提前检查冻结下限，避免不可执行结果进入审核后状态。必须保留调整时的最终校验，并回归取消与调整、取消与库存写入的并发互斥。

### P1：普通业务接口的数量精度在浏览器端丢失

证据：普通库存 VO 使用 BigDecimal，默认输出 JSON 数字；`frontend/src/modules/inventory/types.ts` 等将数量定义为 number，`DocumentLinesEditor.vue` 使用数字输入，盘点结果提交调用 `Number`。AI 工具结果则已把数量转换成字符串。

本轮用本地 Node 执行 JSON 解析，数据库允许的 `99999999999999.9999` 变成 `100000000000000`，`999999999999999.1234` 变成 `999999999999999.1`。这是允许数量范围内可复现的边界风险；本轮未通过浏览器提交这些数量。数据库 BigDecimal 无法恢复浏览器已经丢失的小数。

建议统一数量契约为十进制字符串，覆盖读取、输入、编辑回显和提交；输入用字符串校验，确需计算时才采用十进制计算工具。不能仅修改 TypeScript 类型或显示格式；需验证最大值、四位小数、详情编辑往返和盘点差异。

### P2：首次管理员创建缺少原子性

证据：`AuthenticationApplicationService.run` 没有事务，先插入用户，再查询 ADMIN 角色和插入角色关联；已有同名用户时直接返回。现有测试覆盖成功绑定，未覆盖中途失败。

按代码路径，角色缺失或绑定失败可能留下没有管理员角色的用户；下次启动又因同名用户存在而跳过初始化。该失败路径为静态分析，本轮没有向真实数据库注入故障。

建议把初始化放入公开事务用例，检查角色和写入影响行数，并测试绑定失败整体回滚及失败后的重启恢复。需要同时考虑用户名去空格的一致性和两个实例并发初始化。

## 可靠性与性能优化

### P2：安全库存预警缺少部分变化触发

只有采购完成和销售完成调用 Outbox。冻结、取消释放、调拨收货和盘点调整都会改变可用量，却不触发预警评估。

例如可用量 100、阈值 50，销售冻结 60 后可用量为 40，没有对应事件；若后来已经打开预警，取消恢复可用量也可能没有解除事件。消费者重新查 MySQL 解决的是已触发事件的数据新鲜度，不能补偿没有发生的评估。

建议先确定预警针对“可用量”还是其他业务口径，再为需要覆盖的变化定义事件，继续使用事务 Outbox 和消费幂等。此项涉及扩大现有事件契约，属于后续开发建议，本轮未实施。

### P2：Outbox 发送时持续持有数据库事务

`OutboxPublicationApplicationService.publishNextDue` 在事务内锁行并调用 `transport.publish`；后者等待 RabbitMQ confirm。网络故障期间会占用数据库连接和 Outbox 行锁，批量发布器又逐条串行执行。当前实现可解释、复杂度较低，未测量到实际连接池耗尽或吞吐瓶颈。

先完成真实 MQ 故障组合测试，观察连接占用、积压和恢复情况。若证实有问题，再考虑短事务认领、事务外发送、短事务记录结果；必须补齐认领租约、崩溃恢复及迟到 confirm 处理，并保留重复投递与消费幂等。不能简单把发送移出事务。

### P2：AI 问答只有每轮超时，没有整次期限和取消链路

每轮模型请求独立等待，允许最多八次工具执行，还需要最终模型回答。配置上限下，九次各接近 60 秒的模型请求可能累计接近九分钟，另加业务查询耗时；这只是配置推导，不是实测延迟。前端 AI 请求已单独设置 650 秒超时，不能误判为使用公共 15 秒超时。

页面卸载只设置 `alive=false`，阻止迟到响应显示，不取消请求。建议增加整次问答的时间预算，把剩余时间传给后续调用，支持前端主动取消，并明确服务端终止方式。真实供应商的工具协议和最终回答合规率仍需联调验证，不应仅用假模型结果判断可用性。

### P3：前端主入口体积可以减少

`frontend/src/main.ts` 全量注册 Element Plus 并导入完整样式。本轮生产构建主 JS 为 1,104.40 kB（gzip 366.71 kB），主 CSS 为 364.01 kB（gzip 49.66 kB），仍有大分块提示。业务页面已有路由分块。

建议评估组件和样式按需引入，先记录登录首屏实际下载与加载时间，再比较改动后结果。仅调整分块或提高告警阈值不能证明首屏更快；本轮没有测量首屏时间。
