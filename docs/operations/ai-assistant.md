# AI 仓储助手使用说明

AI 助手通过 Spring AI 对接模型，将自然语言问题转换为受限的业务查询。它可以查库存、单据和流水，解释冻结来源、区间变化和多仓差异；只提供查询与分析，不会自动制单、审核或调整库存。

## 配置并开启

先按根目录 [README](../../README.md) 完成启动和登录。模型 API 账号、Key 与模型权限需由供应商平台提供，聊天网站账号不能直接代替 API 配置。

所有参数放在后端根目录 `.env`，不要将真实 Key 放进前端、配置模板、Dockerfile 或 Git。配置示例：

```dotenv
AI_ENABLED=true
AI_PROVIDER=DEEPSEEK
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=填写账户可调用且支持工具调用的模型名
AI_API_KEY=填写你自己的API密钥
AI_REQUEST_TIMEOUT=20s
AI_TOTAL_TIMEOUT=90s
```

具体获取入口、DeepSeek 和千问示例见 [README 的 AI 配置](../../README.md#6-ai-配置先准备-api再开启助手)。基础地址不要追加 `/chat/completions`，不要使用聊天网页地址。远程服务要求 HTTPS；供应商、Key、地域和模型必须匹配。项目关闭模型思考模式，纯思考模型不适用。

| AI_PROVIDER | 当前适配器默认地址 | 注意 |
|---|---|---|
| DEEPSEEK | https://api.deepseek.com | 模型名显式填写 |
| QWEN | 无，必须填写 | 使用与 Key 地域/工作空间对应的兼容地址 |
| GLM | https://open.bigmodel.cn/api/paas/v4 | 模型名显式填写 |
| DOUBAO | https://ark.cn-beijing.volces.com/api/v3 | 填可用模型名或接入点 ID |
| MOONSHOT | https://api.moonshot.cn/v1 | 模型名显式填写 |
| CUSTOM | 无，必须填写 | 兼容 Chat Completions 和 tools 的服务 |

这些是代码中的默认地址，不保证供应商所有模型均兼容。供应商实际地址和模型以其 API 控制台为准。

修改配置后，IDEA 后端重新运行；完整 Docker 执行：

```powershell
docker compose --profile app up -d --force-recreate backend
```

仅刷新页面或执行容器 restart 不会加载新的容器环境变量。Docker 后端的 localhost 指容器自身，不能直接用于宿主机上的模型服务。

## 在页面使用

1. 登录后进入“AI 仓储助手”。账号需要对应业务读取权限。
2. 使用项目里实际存在的商品、仓库或单号提问；新数据库没有演示库存。
3. 同名资料会显示候选，选择正确项；缺少条件时直接补充，例如“就在白云仓”。
4. 可以连续追问“它的冻结来源是什么”，也可以明确切换商品、仓库或日期。
5. 查看结论对应的证据、查询时间和来源页面；数据变化后点击重新查询。

可尝试的问题：

- “白云仓有哪些商品，可用库存低于20的有哪些？”
- “有哪些销售单还没完成？”
- “今天完成入库的采购单有哪些？按完成时间查。”
- “A商品在一号仓还有多少实际、可用和冻结库存？”
- “A商品在一号仓从2026-10-01到2026-10-03有哪些库存变化？”
- “销售出库单 SOxxx 的状态和明细是什么？”

替换示例名称和单号。区间分析需要一个商品、一个仓库、可选库位，最多92个自然日。单据的创建日期和完成/调整日期是不同条件，提问时写清日期口径。

## 参数与会话

| 配置 | 默认 | 作用 |
|---|---|---|
| AI_ENABLED | false | 是否调用模型 |
| AI_REQUEST_TIMEOUT | 20s | 一轮模型请求时限 |
| AI_TOTAL_TIMEOUT | 90s | 一次任务总执行预算 |
| AI_AGENT_MAX_ROUNDS | 4 | 规划轮数，1～8 |
| AI_AGENT_MAX_TOOL_CALLS | 12 | 累计业务工具调用数，1～24 |
| AI_AGENT_MAX_CONTEXT_BYTES | 65536 | 模型上下文大小限制 |
| AI_AGENT_MAX_SESSIONS | 100 | 全进程会话上限 |
| AI_AGENT_SESSIONS_PER_USER | 2 | 每个用户会话上限 |
| AI_AGENT_HISTORY_TURNS | 10 | 每会话任务历史上限 |
| AI_AGENT_SESSION_TTL | 30m | 空闲会话有效期 |
| AI_AGENT_INPUT_TTL | 5m | 等待选择或补参有效期 |
| AI_MAX_TOOL_CALLS | 6 | 旧同步 questions 接口预算 |

首次使用保留默认值。Agent 会话在后端内存中按用户隔离，重启后失效；浏览器仅保存用户绑定的会话 ID。历史用于理解指代，当前库存每次重新读取 MySQL。页面可取消、重试、清空会话；重新查询会取得当前授权和数据。

## 权限、数据与证据

| 查询 | 所需权限 |
|---|---|
| 商品、仓库、库位资料 | MASTER_DATA_READ |
| 库存、流水及变化分析 | INVENTORY_READ 与基础资料读取权限 |
| 采购、销售、调拨、盘点单据 | 对应单据 READ 权限 |
| 当前冻结来源核对 | 库存、基础资料、销售、调拨读取权限 |

模型不决定授权，每个业务工具重新校验当前权限。模型只规划白名单工具，不能执行任意 SQL、访问任意 URL 或写库存。数量由 MySQL 和后端 BigDecimal 计算，返回十进制字符串，结论绑定实际查询证据。

问句和必要业务查询字段会发送到配置的供应商。Agent 后续规划也可能使用受限的业务观察结果；不要在问题中粘贴密码、Token 或密钥。服务端日志记录状态、耗时和上游错误分类，不记录密钥或完整业务载荷。

一页明细不等于全部记录，冻结不等于实际出库，调拨和盘亏不等于销售消耗。区间变化不能直接推导完整期初/期末余额；查询失败不能解释为零库存。结论不足时保留已有证据和未确定事项。

## 常见问题

| 提示或现象 | 处理 |
|---|---|
| 未启用 / 配置缺失 | 检查 AI_ENABLED、供应商、模型、Key 和基础地址，重新启动后端 |
| 需要选择 / 补充条件 | 选择候选或发送缺少的条件，可继续当前任务 |
| 无数据 | 核对实际名称和筛选条件，先建立业务数据 |
| 权限不足 | 管理员授予对应读取权限；模型不会绕过授权 |
| 上游鉴权 / 余额 / 限流错误 | 到供应商平台检查 API 权限、余额和额度，核对 Key 与地域 |
| 超时 / 工具上限 | 缩小范围或拆分问题，查看已取得的证据 |
| 会话过期 / 后端重启 | 新建会话并重新提问 |
| 健康 UP 但 AI 不可用 | 健康接口仅检查应用和数据库，不检查模型账户与网络 |

当前不支持自动供应商切换、在线秘钥管理、跨实例会话恢复、预测、补货、OCR 或知识库。旧 `POST /api/ai/questions` 同步接口保留兼容；页面使用会话任务接口，其预算和会话行为以 Agent 参数为准。

更多启动排错见 [启动手册](startup.md)，容器配置更新见 [Docker 手册](docker.md)。
