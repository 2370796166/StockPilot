# 仓储查询与分析 Agent

当前 `/ai-assistant` 使用 `AiAgentView` 和会话/任务接口。Spring AI 1.1.8 已实际接入 `OpenAiChatModel`，模型凭据由本机环境配置提供。SDK 自动工具执行关闭，后端控制规划、只读工具、观察、补查与结束；简单业务查询可直接回答。可重复执行的验证步骤与边界见 [测试说明](../testing.md)。

会话只保存确认条件和有限问题历史，用于理解指代；库存结果不作为后续当前库存依据。任务按用户隔离，清空会取消任务并删除该会话。进程重启后会话失效，尚未支持跨实例恢复。候选选择和补参提交当前任务版本，保留原计划；续查重新读取当前数据，旧证据作为历史单独展示。每轮规划与每个工具重新检查 MySQL 当前授权，来源链接还检查单据读取权限。

| Agent 配置 | 默认值 | 限制 |
|---|---|---|
| AI_AGENT_MAX_ROUNDS | 4 | 1～8，暂停续查不重置 |
| AI_AGENT_MAX_TOOL_CALLS | 12 | 1～24，累计工具数 |
| AI_AGENT_MAX_CONTEXT_BYTES | 65536 | UTF-8 上下文 8192～262144 bytes |
| AI_AGENT_MAX_SESSIONS | 100 | 全进程会话上限 |
| AI_AGENT_SESSIONS_PER_USER | 2 | 每用户会话上限 |
| AI_AGENT_HISTORY_TURNS | 10 | 每会话任务历史上限 |
| AI_AGENT_SESSION_TTL | 30m | 空闲会话有效期 |
| AI_AGENT_INPUT_TTL | 5m | 等待选择/补参有效期 |
| AI_TOTAL_TIMEOUT | 90s | 执行总预算，排队计时，等待用户输入暂停 |

执行线程为 2 个、排队容量 16；保留证据限 128 KiB，模型响应限 64 KiB。取消停止尚未开始的步骤，并取消在途模型 HTTP；已开始数据库读取遵守自身短事务/JDBC 超时，不承诺硬中断。页面以短轮询展示业务步骤，保留失败前证据，防止重复提交及迟到响应覆盖。

| 接口 | 用途 |
|---|---|
| POST /api/ai/sessions | 创建用户会话 |
| GET /api/ai/sessions/{id} | 读取条件和历史 |
| DELETE /api/ai/sessions/{id} | 清空并取消 |
| POST /api/ai/sessions/{id}/tasks | question + requestId；同请求幂等，不同问题复用 ID 返回 409 |
| GET /api/ai/tasks/{id} | 进度、证据、回答、版本 |
| POST /api/ai/tasks/{id}/input | version、choices、conditions、refinements，或独立 message；字段补参/候选续查保留查询，文字补充在原任务内重新规划 |
| POST /api/ai/tasks/{id}/cancel | 取消任务 |
| POST /api/ai/tasks/{id}/retry | version、requestId；创建新任务，恢复原确认条件/选择/计划，重新读取业务数据；幂等重试 |

任务状态为 RUNNING、NEEDS_SELECTION、NEEDS_CLARIFICATION、COMPLETED、PARTIAL、FAILED、CANCELLED，reason 区分无权限、无数据、工具失败、模型错误、重复调用、轮数/工具/时间上限等。Answer 包含 conclusions、uncertainties、suggestions；每条结论绑定 evidenceId、事实字段/值、scope、queriedAt、coverage。模型只能通过 `finish_analysis.claims` 引用已成功证据及白名单字段，后端校验索引、字段和值，数量以 BigDecimal 比较；自由文字不能生成业务事实。后端按证据类型解释冻结、实际变化、未完成状态与比较结果，未确定原因明确保留。

证据在任务内分配稳定编号 E1、E2…；选择前证据移入 previousResults 后不重新编号。结论可用 evidenceIds 引用同范围多条证据，facts 的每个字段绑定具体编号。finish_analysis 保存已校验的 claims 选择；relatedEvidence 按商品、仓库、库位和区间核对，区间采用开始/结束日期与时区，派生边界不会导致等价范围误拒。单据详情具有独立范围，关联须由已查询区间单据分组证明单号、业务动作，再核对单据仓库、商品及可选库位；调拨区分源端与目标端。仅数量字段允许 BigDecimal 等价，业务单号、编码及状态必须逐字匹配，001 不能等同 1。区间变化与逐单据汇总可组合解释，明确当前页范围，不宣称分页证据已逐单核对全部变化。

结束前检查最低业务证据要求，余额不能证明区间下降，复合查询必须同时满足比较、区间及单据要求；不足返回 INSUFFICIENT_EVIDENCE 并保留已有结果。该检查为明确业务意图的保守规则，不保证任意自然语言请求都被完整拆解。finish_analysis 不计入业务工具次数；达到规划/工具上限时，已有完整证据可以结束，否则明确报告上限。

任务附 steps（业务标签、状态、证据编号、时间）及 conditionSources（SESSION、USER_INPUT、TOOL_CONFIRMED），不展示模型推理过程。切换商品/仓库/库位或日期会失效旧单据指代；全仓/全部库位查询会清除旧库位条件。当前冻结工具在同一快照提供实际量、可用量及二者差量，用于解释冻结占用。

模型不能自行补出未提供的实体条件。实体条件须来自问题、服务器确认的上下文、用户补参原值或已查询资料；模型将用户提及名称换成编码时，以公开资料Service和剩余预算内只读查询核对，并改回名称继续候选解析，不能绕过同名选择。无来源的条件被移除，目标工具只询问缺失字段。区间排查插入当前库存/冻结查询不会清除原日期，后续流水保留区间；当前数量仍重新读库。

事实field接受data内路径或明确/data观察封装路径，规范化为同一白名单字段后校验准确值。/data本身、未知字段、路径穿越及错误数量仍拒绝。单据关联可由已查区间分组、流水、当前冻结来源或销售列表证明，须匹配单号、类型、仓库、商品和库位；当前冻结不被当作历史区间证据。

页面在本浏览器标签页的 sessionStorage 中仅存用户绑定的会话 ID。返回来源页面后从服务器恢复条件、历史和证据；不把浏览器保存的库存当作事实。网络恢复失败保留会话 ID，可重新连接，404/410 才清理失效标识。提交响应丢失时重试同一 requestId；“重新查询”使用 retry 接口和原任务版本，区分网络重发与重新读取当前业务数据。离开页面取消仍在运行的步骤，保留会话供返回；清空才删除服务端会话。

新增 `query_sales_orders`（按商品/仓库查未完成或指定状态）、`summarize_documents`（完整区间按业务单据汇总，明细分页）、`compare_inventory`（两个仓库的余额、冻结来源与后端差量）。流水支持日期/动作筛选。工具只调用公开业务 Service，没有任意 SQL、模型 URL、跨模块 Mapper 或写操作。模型观察只包含必要白名单，不发送内部备注、操作人、来源链接、JWT 或配置凭据。

## 日常列表查询与自然语言补充（2026-10-08）

- `list_inventory` 支持全部商品或按商品、仓库、库位筛选，不强制指定单个商品。`belowAvailable` 为用户明确提供的非负十进制阈值，SQL 按库存维度严格筛选可用量小于阈值的记录，再分页。不同商品的数量不累加；没有安全库存阈值时不能把此筛选称为预警或预测。
- `list_documents` 只要求 `documentType=PURCHASE/SALES/TRANSFER/COUNT`，仓库、准确状态/UNFINISHED、单号关键词、日期和分页可选。UNFINISHED 排除完成、调整和取消；销售包括草稿、冻结和审核，调拨包括在途。调拨 warehouse 表示源仓，otherWarehouse 表示目标仓。每次执行和展示均校验对应类型的读取权限。
- 单据日期 `dateField=CREATED` 为创建日（默认），`COMPLETED` 为完成入库、出库、收货或盘点调整日；日期成对提供，最多92个自然日，SQL 为开始日零时到结束日次日零时。此能力复用各模块公开 Service，没有新表、迁移或库存写入。
- 等待缺参或候选时，可在输入框发送“就在白云仓”“改查天河仓”等 message。服务端检查版本、敏感内容和预算，保留原问题及旧证据，清除旧待执行计划后重新规划；累计模型/工具/时间预算不重置。文字输入与 choices/conditions/refinements 互斥，同名名称仍交由候选确认。
- 字段补充可进入目标工具的合法可选字段，例如库位查询缺少的仓库；缺失字段会扣除已给参数。通用 MISSING_INPUT 收到条件后重新规划，不再原样执行 clarify。
- 复杂问题可通过 `plan_query.goals` 声明多个工具和范围。结束时每个目标须匹配新的成功/无数据执行及商品、仓库、日期等参数；不同范围的同名工具不能互相替代，一个目标无数据不能跳过其他目标。控制工具不占业务工具次数，但受模型轮次和总预算限制。未声明目标的旧计划仍使用原保守业务意图规则；模型是否完整拆解任意自然语言仍需要实际题集验证。
- 每次规划包含最近最多3条、每条最多1000字的用户查询意图；历史仅用于指代，不作为当前数量或权限依据。

可尝试：“白云仓有哪些商品，可用库存低于20的有哪些？”、“全公司有哪些销售单还没完成？”、“今天完成入库的采购单有哪些？按完成时间查询”。验证步骤见 [测试说明](../testing.md)。

## 旧 questions 接口兼容说明

以下章节说明保留的同步 `POST /api/ai/questions` 接口及旧页面组件行为。其签名续查、单批摘要和客户端断连限制不能代表当前 Agent 页面；其中“没有会话”“没有后台任务”“业务结果不回传”只适用于此兼容入口。

登录管理后台后进入 `/ai-assistant`。分发配置默认关闭 AI；本机可通过 `.env` 启用。不启用模型也可正常使用核心库存业务。模型识别查询意图、选择受限工具；成功业务批次由后端直接生成事实摘要，不再请求模型确认，数量和来源由 MySQL / BigDecimal 与后端权限校验决定，不直接展示模型自由文字作为业务结论。

## 配置

根目录 `.env` 中设置以下变量，修改后重启后端：

| 变量 | 默认值 | 说明 |
|---|---|---|
| AI_ENABLED | false | 是否调用模型 |
| AI_PROVIDER | CUSTOM | CUSTOM、QWEN、DEEPSEEK、GLM、DOUBAO、MOONSHOT |
| AI_BASE_URL | 空 | 覆盖预设地址，不包含 /chat/completions；QWEN/CUSTOM 必填 |
| AI_API_KEY | 空 | 后端密钥，不放入前端或提交到 Git |
| AI_MODEL | 空 | 账户实际可用、支持工具调用/JSON回答/非思考模式的模型或接入点 ID |
| AI_REQUEST_TIMEOUT | 20s | 单次模型 HTTP 时限，100ms～60s |
| AI_TOTAL_TIMEOUT | 90s | 整次问答共享时间预算，100ms～300s；剩余预算限制后续模型请求 |
| AI_MAX_TOOL_CALLS | 6 | 单问题执行工具上限，1～8 |

例如：

```dotenv

AI_PROVIDER=DEEPSEEK
AI_BASE_URL=
AI_MODEL=替换为账户实际可用且支持工具调用的模型名
AI_API_KEY=替换为仅保存在本机的密钥
```

## 查询与权限

| 能力 | 权限与范围 |
|---|---|
| 商品/仓库/库位候选 | MASTER_DATA_READ，同名需用户选择 |
| 单仓/多仓库存 | INVENTORY_READ + MASTER_DATA_READ；仓库全范围汇总、库位分页 |
| 库存流水 | 库存和基础资料读取权限；限定维度的一页流水 |
| 按准确单号查单据 | 对应采购、销售、调拨或盘点 READ 权限 |
| 按准确流水号追溯 | 库存读取 + 来源单据读取权限 |
| 时间段变化汇总 | 库存和基础资料读取；一个商品、仓库、可选库位，最多92个自然日 |
| 当前冻结来源核对 | 库存、基础资料、销售和调拨读取四项权限全部具备 |

每次工具独立检查当前权限，模型和客户端 ID 不决定授权。缺少条件须澄清；候选选择后重新校验，不自动选择第一条。数量以十进制字符串返回，前端不自行用浮点数计算。

候选响应携带 `continuationToken`。点击候选时提交原问题、累计选择及该令牌；服务端核验签名、用户、原问题和五分钟有效期后，直接重跑原工具批次，重新读取当前业务数据，不重新让模型解析。令牌只包含受限查询计划与绑定信息，不包含模型密钥、库存结果或完整聊天记录；签名密钥在服务端进程内随机生成。重启或切换后端实例后原令牌失效，返回 INVALID_ARGUMENTS，用户需重新发送问题。没有通用会话记忆、Redis 会话或新增表。

前端按资料类型与关键词共同保存选择，因此同一问题的两个商品条件不会互相覆盖。候选续查网络失败或取消时保留上次证据和令牌，可在原问题下再次选择重试；令牌仍受服务端有效期和权限检查约束。

示例问题需替换为真实名称/单号：

- “A 商品在一号仓还有多少实际、可用和冻结库存？”
- “查询销售出库单 SOxxx 的状态和明细。”
- “流水 LGxxx 对应哪张业务单据？”
- “A 商品在一号仓从2026-10-01到2026-10-03有哪些库存变化？按业务动作汇总。”
- “A 商品在一号仓当前冻结来自哪些销售单和调拨单？”

## 证据与限制

结果包含查询时间、后端数量、分页范围和来源页面。时间区间包含起止日，按 Asia/Shanghai 计算；区间差量不等于期初/期末余额，不证明完整版本链。冻结/释放不是实际出库，调拨/盘亏不是销售消耗。

当前冻结来源只统计销售 RESERVED/APPROVED 和源端调拨 SUBMITTED/APPROVED；取消、出库、调出、在途和盘点维度锁不计入当前占用。余额与来源总量/分页在10秒 REPEATABLE_READ只读快照内核对，总量相同不证明逐库位/逐单据一致；差异保留，不自动修正库存。

模型请求不持有数据库事务。工具白名单拒绝 SQL、额外参数或模型网络地址；业务批次完成后不把余额、单据、流水结果回传供应商整理。资料查找继续规划时只发送白名单资料字段，不发送密码、JWT、后台密钥、操作人身份或备注。资料补全通过基础资料公开 Service 按商品、仓库、库位分别批量读取必要展示字段；库位候选分页按该页不同仓库 ID 一次批量补全仓库编码，空页不补查，不逐条读取仓库详情。单次问答内重复参数规范化后可复用已授权结果，保留原查询时间；复用前仍检查权限及来源，不跨问题缓存库存。

单次问题最多1000字符，候选选择最多3项，每页最多20项；续查令牌最多32768字符，模型响应最多64 KiB，模型文字校验上限2000字符。业务查询批次成功后直接返回全部已查证据，不追加最终模型请求，工具计划附带的自由文字也不会成为事实摘要。资料查找轮次仍受累计工具上限约束；达到查询上限后可进行一次不提供工具的 JSON 结束回复，若仍请求工具则拒绝。仅资料查找路径最多为工具上限加一次模型请求（配置最大值时最多九次），不是实际耗时或费用测量。

不是流式交互，前端 HTTP 时限为310秒，覆盖后端允许的最大总预算。默认总预算90秒，每轮不重置，模型网络等待采用单轮时限与剩余预算中的较小值。每个读取工具执行前后检查预算，整个工具的名称解析、业务查询及资料补全共享 REPEATABLE_READ 只读事务；事务时限为剩余预算向上取整到秒与十秒的较小值。JDBC 事务超时是秒级限制，不等于硬终止整个请求或连接池等待。澄清工具不访问数据库。超限返回 QUESTION_TIMEOUT，并保留已查结构化证据。

“取消等待”及离开页面会中止浏览器 HTTP 请求，不显示系统错误或回填迟到结果。同步 Servlet 请求在浏览器断连后不保证立即终止服务端执行；服务端仍受时间预算约束。已开始的数据库查询不会因前端取消被硬中断，受其自身事务/JDBC超时约束，本版没有后台任务及取消管理接口。

## 状态与验证边界

关闭、配置缺失、无权限、无数据、缺参、候选选择、查询失败、超时、模型错误、无效响应和工具上限分别显示状态。查询失败不等于零库存；资料查找后续模型规划失败保留已查结构化结果，成功业务批次不再依赖模型整理。

工具返回非 OK 业务状态时明确回滚本次只读快照，避免内层读取异常导致的回滚标记在提交时覆盖 NO_DATA 等状态。数据库事务获取或执行失败仍为 QUERY_FAILED，不当作无数据。

接口为 `POST /api/ai/questions`，请求包含 `question`、`selections` 和可选 `continuationToken`；响应使用统一 ApiResponse，含 `status`、`answer`、`results`、`queriedAt` 和可选 `continuationToken`。

脱敏日志以 `aiRequestId` 串联问答、模型轮次和工具阶段，记录固定状态、耗时、token 用量及上游鉴权/余额/限流/服务错误分类；不记录问题、工具参数、业务载荷、Token、密钥或上游错误正文。对外仍用 MODEL_ERROR 表示上游失败，详细分类供运维排查。没有自动网络重试或自动切换供应商。

常规自动化测试使用 Mockito、MockMvc、组件测试和本机假供应商。真实模型需显式运行验收脚本；合成公开 Service、真实 MySQL/HTTP 和浏览器组合是不同验证层次，不能互相替代。当前日常查询的四问真实 DeepSeek 题集尚未执行，不能以模拟模型结果承诺真实模型语义完成率；其他供应商也未充分联调。验证步骤见 [测试说明](../testing.md)。

手动真实模型测试：先执行 `mvn -s .mvn/settings.xml clean test`，再执行 `python -B scripts/test-ai-live.py`。默认读取本机 `.env` 的 DEEPSEEK 密钥；`--prompt-key` 可改用无回显输入。查询官方模型列表后通过进程 stdin 传给验收类，不复制到命令参数或子进程环境，不读取业务数据库。脚本不写密钥文件；`.env` 由用户自行保存且被 Git 忽略，不能上传或复制进 `.env.example`。每轮最多28次模型调用，每次输出最多1200 tokens；普通 `mvn test` 不调用真实模型。离线加载检查可运行 `python -B scripts/test_ai_live_config.py`，只使用合成凭据。JSON 和工具选择约定参考 [DeepSeek Chat Completions 官方文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

没有 AI 写操作、自动审核、库存调整、预测、补货、OCR、知识库或会话记忆。使用前先按 [启动手册](startup.md) 确认基础业务正常。
