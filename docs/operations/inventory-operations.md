# 库存保障与异常处理

## 安全库存

“安全库存”按仓库、库位、商品创建阈值规则。可用库存严格低于阈值时预警，等于阈值时不预警。修改阈值或启停规则后立即重新评估；库存维度尚无余额时按零库存评估，查询失败会报错，不会按零处理。停用规则会解除对应当前预警。

每个维度只有一条规则，修改携带当前版本；重复创建或旧版本修改返回409。规则维度创建后固定，要调整阈值就修改原规则。规则管理需要 `SAFETY_STOCK_WRITE`，查询需要 `SAFETY_STOCK_READ`。已有库存在消息开关关闭时不会通过异步事件自动更新预警，可人工点击“重新评估”；开启消息后随库存变化事件更新。列表数量为上次评估值。

## 消息异常

“消息异常”展示失败阶段、原因和最近100条轨迹。管理员修复故障后填写说明并重试。发布失败重新进入 Outbox 等待调度，发布确认后才显示已处理；消费失败用原始事件同步执行预警处理，保留原消息 ID 与消费幂等记录。此入口不执行库存扣减或补偿数量。

不支持的版本、无效载荷、变化后的失败记录不能重试。可以填写真实核查结论后“标记已处理”；该动作只记录人工结论，不代表消息重新投递成功。不得编辑原事件、删除幂等记录或创建新 ID 绕过防重。发布功能关闭时不能提交发布重试。

读取与处理分别需要 `MESSAGE_FAILURE_READ` / `MESSAGE_FAILURE_WRITE`。全局异常记录可能关联多个仓库，因此还要求账号具有全仓范围。

## 库存对账

选择一个仓库、库位、商品，点击“开始对账”。同一短期只读快照内核对三数量不变量、完整流水累计、流水起点和版本链、流水末值、有效销售/调拨占用，以及调拨单、独立在途与两端流水。

对账只报告差异，不修改库存。没有余额或缺少流水证据不会显示一致。结果只覆盖所选维度；在线核对最多200条相关调拨明细，超过时整次拒绝，不输出部分结果或声称全库一致。检查可能受10秒事务超时限制，大数据量需离线对账。

需要 `INVENTORY_RECONCILE`、库存/销售/调拨读取权限和全仓范围，以避免把不可见单据当作库存缺口。AI 的完整冻结来源核对和多仓比较同样要求全仓范围；受限账号仍可查询自身范围内的余额、流水和单据。发现差异后追溯原始单据与流水，按正常业务流程或经过审计的专用修复方案处理。

## 采购与盘点退回

采购草稿可关联启用的供应商，详情保留供应商名称快照。历史单据没有供应商关联时保持为空。采购提交后可以由审核人员填写原因退回草稿；草稿、已提交和已审核单据可填写原因取消，已完成单据不可取消。退回前的仓库、供应商名称快照、备注、提交信息与明细，以及取消原因均保留独立证据；退回后编辑单据不会覆盖这些证据。

盘点已提交时可由审核人员退回“盘点中”，原始实盘结果保留为不可变证据，维度锁继续存在，可重新录入和提交。退回不改变库存、不释放盘点锁。取消和调整按既有规则释放锁。各类单据最多200条明细/盘点维度。

采购退回后修改仓库，历史退回/取消记录仍按证据中的原仓库授权展示。账号可以读取当前单据，不代表可以读取它曾经关联的其他仓库；原仓库未授权或历史证据无法确认仓库时，该记录对受限账号隐藏。证据仍完整保存在数据库，全仓账号可查阅。AI 恢复历史证据也重新检查其中的仓库范围。

修改、退回和取消应携带最新版本。请求超时后先查询单据状态再决定重试；完成动作重复请求仍返回409，不能因为网络错误重新创建单据。数据库并发事务冲突返回409，重新查询后重试完整业务动作。
