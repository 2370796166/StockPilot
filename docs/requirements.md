# StockPilot 产品需求基线

## 项目背景与目标用户

StockPilot 面向中小型制造或电商企业，解决采购到货、销售占用及出库、库存追踪、多仓调拨、盘点差异和安全库存预警问题。项目用于软件工程本科生的 Java 实习作品，但所有技术点必须能够结合真实代码解释。

当前代码已实现后端基础工程、基础资料、认证、RBAC、基础审计、库存余额和库存流水底座，以及采购入库、销售出库、仓库间调拨与静态库存盘点闭环。

## 用户角色

最终 MVP 需求只定义三个逻辑角色：

- `ADMIN`：管理员，负责系统配置、用户权限和基础资料。
- `OPERATOR`：业务员，负责创建和提交采购、销售等业务单据；MVP 不再细分采购员、销售员和仓库操作员。
- `AUDITOR`：审核员，负责审核授权范围内的业务单据。

当前代码和数据库默认角色已与最终 MVP 对齐。Flyway `V0.3.2` 将早期迁移中的六个细分角色收敛为上述三个角色，并迁移已有用户角色关系；库存和单据开发继续按照三个逻辑角色控制 MVP 复杂度。

## 当前产品边界

StockPilot 第一版聚焦单企业、多仓库场景。库存粒度为仓库、库位、SKU，不做多租户、批次、序列号、保质期和复杂财务核算。当前开发顺序以核心正确性为准，而不是以模块数量为准。

## MVP 必做功能与实现状态

第 1、2、3、4、5、6 项已经实现并验证；第 7 项已覆盖采购、销售、调拨和盘点相关场景：

1. **已实现并验证——基础资料**：仓库、库位、单层商品分类、SKU、供应商；支持创建、修改、详情、条件分页和启用/停用，不提供删除接口。编码创建后不可修改。
2. **已实现并验证——认证授权基础能力**：用户名密码、BCrypt、JWT Access Token、数据库实时权限、接口级 RBAC、三个 MVP 默认角色和基础安全审计。不包含 Refresh Token、Redis 黑名单和仓库级数据权限。
3. **已实现并验证——库存底座**：库存余额、不可变流水、按仓库/库位/SKU分页查询、内部零库存初始化和带乐观锁的差量变更服务；没有公开写接口或手工调整功能。
4. **已实现并验证——采购入库**：草稿创建和编辑、提交、审核、确认入库、防重复入库、同单并发串行化及事务回滚。
5. **已实现并验证——销售出库**：草稿创建和编辑、原子冻结、审核、实际出库、取消释放、防超卖和业务幂等。
6. **已实现并验证——库存流水基础模型**：分别记录实际量、可用量、冻结量的前值、变化值和后值，以及业务类型、业务单号、操作人和余额版本链。
7. **已实现并验证——核心自动化测试**：采购入库、销售出库、仓库间调拨和静态盘点已覆盖事务回滚、重复请求和并发。
8. **已实现并验证——RabbitMQ 安全库存预警及消费幂等**：入库/出库完成写 Outbox，消费者查询 MySQL 最新库存，支持有限重试、死信和异常记录。

### 最终 MVP 默认角色与当前实现

最终 MVP 与当前默认角色一致：

```text
ADMIN
OPERATOR
AUDITOR
```

当前权限基线为：`ADMIN` 拥有现有全部权限；`OPERATOR` 可读取基础资料和库存，操作采购、销售、调拨及盘点的非审核动作；`AUDITOR` 可读取基础资料、审计、库存和业务单据，并执行采购、销售、调拨及盘点审核。盘点独立使用 `INVENTORY_COUNT_READ/WRITE/APPROVE/ADJUST`。

### 当前已完成：库存中心与核心库存单据

当前代码已经完成以下范围：

- 库存余额表和库存流水表；
- 按仓库、库位、SKU 查询余额和流水；
- 明确语义的入库增加、冻结、释放、已冻结出库能力；
- MySQL 条件更新、乐观锁、唯一约束和流水幂等；
- 事务、并发和数据不变量测试；
- 不对外提供任意修改库存数量的通用接口。

采购入库状态为 `DRAFT → SUBMITTED → APPROVED → COMPLETED`。当前没有 `REJECTED` 或 `CANCELLED`，也不强制制单人与审核人身份不同；默认角色权限已经形成职责分离，管理员保留全流程能力。销售出库使用 `DRAFT → RESERVED → APPROVED → COMPLETED`，并允许冻结后、实际出库前取消释放。仓库间调拨和静态盘点均已按第二阶段授权实现。

## 第二阶段进阶功能

调拨和盘点已在用户明确授权后实现并验证；其余仍为“计划中”：

- 两阶段库存调拨：源仓冻结、调出、独立在途记录、目标仓收货（已实现并验证）。
- 库存盘点：快照、静态维度锁、实盘、差异审核和库存调整（已实现并验证）。
- Redis查询缓存：SKU和仓库单键详情、短期空值和不可用降级（已实现并通过常规测试）；库存余额暂不缓存。
- 用户可操作仓库的数据权限与创建人/审核人职责分离；当前 RBAC 仅为接口级权限，不包含仓库级数据范围。
- Redis 请求幂等令牌、登录失败限流。
- 异常消息人工补偿管理 API；当前已落补偿记录表和状态字段，但未开放管理接口。
- Vue 3 管理端、操作日志增强、应用容器化。

## 暂不实现

- 多企业 SaaS、多租户隔离。
- Spring Cloud、微服务、Kubernetes、分布式事务。
- 批次、保质期、序列号和复杂库位策略。
- 多级审批或工作流引擎。
- 部分入库、部分出库、部分调拨收货、调拨货损和退运。
- 库存成本、财务结算、自动补货和销量预测。
- 移动端、扫码枪、条码打印和复杂分析大屏。
- 未经真实测试支撑的性能承诺。

## 核心业务流程

### 采购入库（已实现并验证）

创建草稿 → 提交 → 审核 → 确认收货 → 增加实际/可用库存 → 写库存流水 → 完成。

### 销售出库（已实现并验证）

创建草稿 → 提交并原子冻结 → 审核 → 确认出库 → 同时扣减实际量和冻结量 → 写库存流水 → 完成。取消未完成单据时释放冻结量。

### 安全库存预警（已实现并验证）

库存事务和 Outbox 记录共同提交 → 提交后由调度器发布事件 → 消费者查询 MySQL 最新可用库存 → 创建、更新或解除预警。异步失败不得破坏库存结果；安全阈值维度为仓库 + 库位 + SKU，低于阈值时预警。

### 调拨与盘点（第二阶段，已实现并验证）

调拨采用源仓冻结、调出进入在途、目标仓收货的两阶段流程。盘点采用静态方案：创建时保存快照并锁定选定库存维度，录入实盘、提交审核后一次性调整并释放锁。

## 核心业务规则

- MySQL 是库存唯一权威来源。
- 库存唯一维度计划为仓库、库位、SKU。
- 正常情况下 `actual = available + frozen`，三者不得为负。
- 可用量由实际量减冻结量得到，不得维护为互相独立的第三份权威数据。
- 草稿不修改库存；采购确认收货才增加库存；销售提交冻结后才能出库。
- 单据状态、库存余额、明细占用和库存流水必须在同一个 MySQL 本地事务中变化。
- 多明细操作任一失败则整单回滚。
- 库存充足判断必须使用 MySQL 原子条件更新，不能只在 Java 中先查后改。
- 重复提交、取消、确认入库或确认出库不得重复生效。

## 非功能需求

- Java 17 编译，模块化单体，后端优先。
- 参数校验、统一错误响应和不泄露内部细节的异常处理。
- 密码使用 BCrypt；JWT 密钥由环境变量提供；敏感信息不得写入日志或仓库。
- 列表分页，索引根据真实查询和 `EXPLAIN` 调整。
- 核心规则具有自动化测试，README 能让新开发者启动项目。
- 不虚构性能指标；若压测，必须记录环境、数据规模和脚本。

## 项目最终验收标准

- 采购入库和销售冻结出库能够完整演示。
- 库存不足和并发争抢不会产生负库存或超卖。
- 重复请求不会重复修改库存。
- 单据、库存和流水在异常时共同回滚且可追踪。
- MQ 消费者可处理重复消息，异步失败不破坏库存。
- 核心规则有自动化测试证明，运行和限制在 README 中说明。
