# 当前阶段

采购入库闭环阶段已完成并验证。项目仍为单 Maven 模块后端，已包含采购入库单，不包含销售、调拨或盘点单据。

# 已实现

- 用户、角色、权限的创建、修改、查询和启用/停用。
- 用户角色、角色权限关联整体替换。
- BCrypt 密码哈希；用户响应与审计日志均不返回密码哈希。
- JWT Access Token 登录，无 Refresh Token、Redis 会话或 OAuth2。
- 每次请求从 MySQL 重载用户启停状态和权限，停用或权限调整即时生效。
- Spring Security 与方法级权限；统一 401、403 响应。
- `ADMIN`、`OPERATOR`、`AUDITOR` 三个预置角色和安全管理/基础资料权限种子。
- 安全接口使用 URL 与方法注解双层授权，未知接口默认拒绝；授权关系变更由独立 `SECURITY_GRANT` 控制。
- 登录结果和安全管理关键写操作审计，摘要不记录密码或完整 Token。
- JWT 密钥和可选首次管理员凭据只从环境变量读取。
- `inventory_balance`、`inventory_ledger` 表，联合唯一维度、数量 `CHECK`、版本链和业务动作唯一约束。
- 库存余额、流水分页查询及 `INVENTORY_READ` 权限；没有公开库存写接口。
- 内部零库存初始化和差量变更服务；使用预期版本条件更新，余额和流水处于同一事务。
- 流水 Mapper 只允许新增、查询，Controller 只返回 VO。
- 采购入库单 `DRAFT → SUBMITTED → APPROVED → COMPLETED` 状态闭环，只有草稿可整体替换明细。
- 采购入库读、写/提交、审核、完成四类权限；默认角色按业务员、审核员职责分配。
- 执行入库使用单据行锁，库存余额、库存流水和完成状态处于同一事务；单号和流水业务动作唯一约束提供最终幂等防线。

# 已知限制

- MySQL 镜像仍为浮动标签 `mysql:8.0`。
- 全新空数据卷重放初始化脚本未验证，不得为验证删除现有卷。
- JWT 为自包含 Access Token；本阶段没有主动撤销单个令牌能力。每次请求会重载用户状态和权限，因此用户停用、角色停用、权限停用及授权调整会让已有 Token 的实际访问能力立即失效；但单个 Token 无法在用户仍启用时单独撤销。
- 真实验证在本地数据库保留了 `codex_verify_admin` 和一个 `verify_viewer_*` 用户及对应审计记录，未物理删除，以保留审计链；这些账号仅用于本地验证，不是产品默认账号。
- 当前 `master` 的 HEAD 仍为 `f4482a3` 并与 `origin/master` 对齐，但库存底座、角色迁移、采购入库及相关测试和文档都位于未提交工作区，不能称为已提交基线。
- 常规测试不连接真实 MySQL；`mysql-it` 配置依赖本地 Compose MySQL，并使用自动创建和删除的专用测试库验证采购入库并发与事务回滚。
- 安全审计主要覆盖登录和安全管理成功写操作；它不能替代库存流水，也不能保证所有事务失败都留下审计记录。
- 库存流水在应用层不可修改或删除，但当前开发数据库运行账号拥有库级权限，仍可通过直连 SQL 修改；生产级迁移账号/运行账号拆分尚未实施。
- 工作区存在 `.idea`、`.m2`、`target` 和本地启动日志，但均被 `.gitignore` 覆盖；本轮未删除用户文件。
