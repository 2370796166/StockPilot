# 已实现

- 用户、角色、权限的创建、修改、查询和启用/停用。
- 用户角色、角色权限关联整体替换。
- BCrypt 密码哈希；用户响应与审计日志均不返回密码哈希。
- JWT Access Token 登录，无 Refresh Token、Redis 会话或 OAuth2。
- 当前用户接口 `GET /api/auth/me` 返回当前登录用户、有效角色和实时权限，供管理后台建立权限菜单与路由守卫。
- 每次请求从 MySQL 重载用户启停状态和权限，停用或权限调整即时生效。
- Spring Security 与方法级权限；统一 401、403 响应。
- `ADMIN`、`OPERATOR`、`AUDITOR` 三个预置角色和安全管理/基础资料权限种子。
- 安全接口使用 URL 与方法注解双层授权，未知接口默认拒绝；授权关系变更由独立 `SECURITY_GRANT` 控制。
- 登录结果和安全管理关键写操作审计，摘要不记录密码或完整 Token。
- JWT 密钥和可选首次管理员凭据只从环境变量读取。
- `inventory_balance`、`inventory_ledger` 表，联合唯一维度、数量 `CHECK`、版本链和业务动作唯一约束。
- 库存余额、流水分页查询及 `INVENTORY_READ` 权限；没有公开库存写接口。
- 内部零库存初始化和差量变更服务；使用预期版本条件更新，余额和流水处于同一事务。
- 流水 Mapper 只允许新增、查询，Controller 只返回 VO。
- 采购入库单 `DRAFT → SUBMITTED → APPROVED → COMPLETED` 状态闭环，只有草稿可整体替换明细。
- 采购入库读、写/提交、审核、完成四类权限；默认角色按业务员、审核员职责分配。
- 执行入库使用单据行锁，库存余额、库存流水和完成状态处于同一事务；单号和流水业务动作唯一约束提供最终幂等防线。
- 销售出库单 `DRAFT → RESERVED → APPROVED → COMPLETED` 主流程，以及 `RESERVED/APPROVED → CANCELLED` 释放流程。
- 销售冻结、实际出库、取消释放使用库存数量下限条件更新，分别写 `OUTBOUND_FREEZE`、`OUTBOUND_SHIP`、`OUTBOUND_RELEASE` 流水，并与单据状态处于同一事务。
- 仓库间调拨 `DRAFT → SUBMITTED → APPROVED → OUTBOUND_COMPLETED → IN_TRANSIT → COMPLETED` 闭环；提交冻结源库存，调出建立独立在途记录，目标收货清理在途并增加目标库存。
- 调拨 `SUBMITTED`、`APPROVED` 可取消释放；调出后禁止普通取消。源端和目标端分别使用稳定的多明细更新顺序。
- 静态盘点 `DRAFT → COUNTING → SUBMITTED → APPROVED → ADJUSTED` 闭环；创建时保存库存三字段与版本快照并建立维度锁，审核后一次性调整并释放锁。
- 盘点差异自动计算；盘盈/盘亏同量改变实际和可用库存，冻结库存不变，实盘小于冻结量时拒绝调整。流水保存账面量、实盘量、差异和原因。
- SKU、仓库单键详情采用可关闭的Redis Cache Aside；正常值TTL 30分钟，不存在值TTL 60秒，更新和启停在MySQL成功后删除缓存。
- Redis值使用`schemaVersion=1`的JSON信封和`stockpilot:v1` Key前缀；连接、读写、删除或反序列化失败均降级MySQL。库存余额、流水、业务校验和最终幂等不使用Redis。
- 入库完成、出库完成分别产生 `stockpilot.purchase-receipt.completed` v1、`stockpilot.sales-outbound.completed` v1 事件；消息包含 UUID、业务单号和受影响库存维度，不包含完整数据库实体。
- 成功事件采用简化事务性 Outbox：与业务事务共同提交，提交前不发送；RabbitMQ 不参与库存最终扣减。发布使用持久消息、mandatory、confirm/return，失败最多尝试8次。
- 消费者允许重复投递，以消息ID+消费者名唯一键幂等；每次处理查询MySQL最新可用库存，低于仓库+库位+SKU阈值时打开预警，恢复后解除。
- 消费失败最多尝试3次，异常不静默吞掉；永久失败重发至持久死信队列并写异常补偿记录。消息各阶段写追踪日志。
- Vue 3 + TypeScript + Vite 管理后台第一轮：登录、整体布局、首页入口、统一请求层、Token/401/403/业务错误处理、权限路由，以及仓库、库位、SKU、供应商页面。
- 四个基础资料页面均调用真实后端接口，列表使用服务端分页；写按钮按 `MASTER_DATA_WRITE` 展示，新增/修改防重复提交，启停操作二次确认。首页不使用虚构统计数据。
- 2026-08-22 管理后台补齐商品分类、采购入库、销售出库、库存余额、库存流水、仓库间调拨、静态盘点、用户和角色页面。业务动作按钮同时检查当前权限和后端真实前置状态，关键动作二次确认，后端仍是权限、状态机与库存正确性的最终保障。
- 单据、库存、调拨、盘点和安全管理请求层均按真实 Controller、Request 与 VO 编写；采购列表没有后端状态筛选，因此前端未提供虚假筛选。角色页面通过真实权限列表配置角色权限，用户页面通过真实角色列表分配角色。

# 已知限制

- MySQL 镜像仍为浮动标签 `mysql:8.0`。
- Redis镜像使用`redis:7.2-alpine`，缓存默认关闭；本阶段没有执行真实Redis容器读写。
- RabbitMQ镜像使用`rabbitmq:3.13-management-alpine`，消息功能默认关闭。Outbox与消费幂等实现的是可恢复、允许重复的交付，不是“绝不丢失/绝不重复”；人工补偿记录已有数据库结构，但尚无管理API。
- 后端没有首页统计聚合接口，因此第一轮首页只展示真实用户、角色和可访问模块；未展示伪造的库存、单据或预警数字。
- 后端供应商模型当前只有编码、名称、状态和备注，管理后台不能维护联系人、电话或地址。后端也没有基础资料专用下拉查询接口，前端选择器复用服务端分页并限制每次20条远程搜索。
- 本轮采用Vite开发代理访问同源 `/api`，后端未新增跨域配置。未执行浏览器到真实MySQL后端的登录与CRUD联调。
- 全新空数据卷重放初始化脚本未验证，不得为验证删除现有卷。
- JWT 为自包含 Access Token；本阶段没有主动撤销单个令牌能力。每次请求会重载用户状态和权限，因此用户停用、角色停用、权限停用及授权调整会让已有 Token 的实际访问能力立即失效；但单个 Token 无法在用户仍启用时单独撤销。
- 真实验证在本地数据库保留了 `codex_verify_admin` 和一个 `verify_viewer_*` 用户及对应审计记录，未物理删除，以保留审计链；这些账号仅用于本地验证，不是产品默认账号。
- 当前 `master` 的 HEAD 为 `d4fe5fc` 并与 `origin/master` 对齐；销售出库、仓库间调拨、静态盘点及相关测试和文档仍位于未提交工作区，不能称为已提交基线。
- 常规测试不连接真实 MySQL；`mysql-it` 依赖本地 Compose MySQL，`rabbit-it` 还依赖本地 Compose RabbitMQ。两类配置均使用自动创建和删除的专用测试库。
- 安全审计主要覆盖登录和安全管理成功写操作；它不能替代库存流水，也不能保证所有事务失败都留下审计记录。
- 库存流水在应用层不可修改或删除，但当前开发数据库运行账号拥有库级权限，仍可通过直连 SQL 修改；生产级迁移账号/运行账号拆分尚未实施。
